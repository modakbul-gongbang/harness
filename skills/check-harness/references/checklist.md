# 종합 점검 계약

각 ID는 독립적으로 보고한다.
필수/권장은 프로젝트 지침과 실제 작업을 근거로 정하며, 파일 개수나 사용량으로 정하지 않는다.
구성 검사와 동작 검사를 한 PASS로 합치지 않는다.

| ID | 영역 | 확인할 내용 | PASS에 필요한 증거 |
|---|---|---|---|
| ENV1 | 실행 환경 | 언어 런타임·패키지 관리자·wrapper | manifest 요구와 실제 버전/PATH 일치; 프로젝트 런타임과 LSP 런타임 구분 |
| ENV2 | 재현성 | 설치·실행 명령과 의존성 고정 | 실제 경로와 wrapper/lockfile, README 명령 일치 |
| LSP1 | 코드 탐색 구성 | 언어별 plugin 활성화 + 서버 binary + 필요 런타임 | 세 가지를 각각 확인; IDE 확장이나 캐시 존재만으로 불가 |
| LSP2 | 코드 탐색 동작 | 대표 심볼의 정의·참조 찾기 | 실제 LSP 호출 결과가 읽은 소스의 정의/알려진 참조 위치와 일치 |
| CTX1 | 프로젝트 안내 | 목적·실행·검증·가이드 진입점 | 적용되는 CLAUDE.md와 링크의 존재·정확성; 없으면 FAIL |
| CTX2 | 로딩과 일관성 | 중복·충돌·불필요한 상시 컨텍스트 | context-review.md에 따라 길이·역할·중복·충돌·참조 단계·실제 로딩 검토; 길이나 분할 취향 자체는 FAIL 아님 |
| SAFE1 | 작업 권한 | allow/deny/ask·관리 정책·sandbox | 프로젝트 위험에 맞는 경계 확인; 확인 불가 계층 명시 |
| SAFE2 | 민감 정보 | Git 유출 방지와 도구 접근 경계 | gitignore와 읽기/쓰기 제한을 별도 확인; 비밀값 자체를 읽지 않음 |
| HOOK1 | Hook 구성 | 활성 이벤트·matcher·실행 경로·입출력 계약 | 실제 적용 설정과 연결된 구현 확인; 빈 이벤트 배열은 Hook 없음 |
| HOOK2 | Hook 동작 | 정상·실패·비대상·malformed 처리 | 안전한 fixture에서 기대 exit/output 관찰; Stop이면 재진입·BLOCKED 종료도 확인 |
| TEST1 | 검증 구성 | 테스트·lint·타입검사·build의 공통 진입점 | 해당 명령, 실제 테스트 task/plugin/config와 테스트 소스 확인; wrapper/manifest 존재만으로 불가 |
| TEST2 | 검증 실행 | 로컬 공통 명령의 실제 결과 | 이번 실행 종료코드와 테스트 결과; 0 tests를 성공 증거로 쓰지 않음 |
| CI1 | 팀 재현 | CI에서 같은 검증 실행 | workflow 경로·working-directory·트리거·공통 명령 확인; 원격 성공과 구분 |
| TOOL1 | 외부/화면 도구 | 필요한 MCP 또는 CLI, 브라우저 도구 | 필요한 작업을 지원하는 구성 확인; 외부 필요가 없으면 N/A |
| TOOL2 | 도구 동작 | 필요한 도구의 안전한 읽기 동작 | 이번 연결/조회 성공; 설정만 있으면 UNKNOWN |
| FLOW1 | 작업 절차 | 요구·범위·AC·조사·구현·검증 | 팀이 쓰는 절차에 연결되고 중복 스킬/과도한 승인 루프 없음 |
| FLOW2 | 독립 검증 | 구현과 검증의 책임·증거 분리 | verifier가 같은 요구/가이드를 직접 읽고 검사한 실제 증거, 코드 수정과 판정 역할 분리 |
| LEARN1 | 개선 | 반복 문제의 방지·정리 | 확인 가능한 문제와 수정/삭제/통합의 연결; 기록 없으면 UNKNOWN, 추가 횟수로 평가 안 함 |

## 적용 예

- 문서 전용: LSP와 애플리케이션 테스트는 N/A 가능, 링크 검증 명령은 TEST1에서 평가.
- Java 앱: LSP1은 보통 권장, JDK와 Gradle/Maven은 개발에 필수.
- Hook이 없어도 CI나 권한 설정으로 목적을 충분히 달성하면 HOOK1/2는 N/A 가능.
- Stop gate를 사용하면 HOOK2의 bounded retry와 실패 종료는 필수 검증 항목.
- MCP 대신 CLI를 써도 TOOL1/2를 동일하게 평가.
- 독립 검증 증거가 없으면 FLOW2는 UNKNOWN이며 reviewer 파일 이름만으로 PASS 불가.
- 사용하지 않은 비상 복구 스킬을 사용량만으로 삭제 권고하지 않는다.
